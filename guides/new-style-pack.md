# 新建风格包规范

> 本协议填补原 guides/ 的空白：此前只有"探索/生成/编译/维护"，没有
> **"如何创建一个新风格"** 的流程。风格包是本库最重要的可复用单元，必须有明确门槛。

## 1. 三种粒度，先判断你要建哪一种

| 粒度 | 何时使用 | 产物 |
|---|---|---|
| **风格运动（Movement）** | 有独立历史脉络、可跨年代 | `atlas/taxonomy/movements/<name>.md` |
| **子风格（Substyle）** | 从属于某运动，共享视觉语法但有独立走向 | `atlas/taxonomy/movements/<movement>-<sub>.md` |
| **风格家族（Style Family）** | 包含多个子风格且共享"视觉语法"的运动 | Movement 页 + 多个 Substyle 页 + 家族共性段 |

**判断标准**：如果多个分支共享**同一套视觉语法**（如视觉系共享"戏剧妆造 + 非日常造型"），
那它应该建成**风格家族**，而不是硬塞成一个子风格。`[本库实践：Visual Kei 即按此处理]`

## 2. 新建风格运动 Checklist

### 必需（缺一不可）

- [ ] **定义 Definition**：一句话说清它是什么，以及**它不是什么**（边界）
- [ ] **时代脉络 Timeline**：至少 3 个时期，最好有代表作品/人名
- [ ] **视觉特征 Visual Cues**：按色彩/妆容/发型/服装/材质/气质分类
- [ ] **Prompt Keywords**：英文词组，逗号分隔，可直接用于生成
- [ ] **适用与搭配**：链接到至少 3 个已有原子元素页
- [ ] **与其他风格的边界**：用「易混 / 反例」表格明确区别
- [ ] **来源 Sources**：至少 1 个可追溯链接
- [ ] **frontmatter**：`type` / `title` / `description` / `tags` / `status` / `generated`

### 建议

- [ ] **母题 Motifs**：反复出现的视觉符号
- [ ] **待补 To Be Built**：明确后续要补什么（诚实标注缺口）

## 3. 新建子风格 Checklist

子风格比运动轻量，但必须**能独立指导生成**：

- [ ] 与母风格的关系（继承什么、反叛什么）
- [ ] 色彩方案（可引用已有色板或新建）
- [ ] 妆容 / 发型 / 服装 / 材质的**具体选择**（指向原子页）
- [ ] 气质一句话
- [ ] Prompt Keywords
- [ ] **与其他子风格的边界表**（这是最容易含混的地方）
- [ ] 变体 Variants（内部细分）

## 4. 风格家族：额外要求

若要建成"家族"，除各分支页外**必须**有：

- [ ] 家族根页（Movement 页）
- [ ] **视觉语法 Visual Grammar** 段：所有分支**共享**的那几条原则
      （这是"家族"成立的依据，不可省略）
- [ ] **分支对照表**：一张表列出所有分支的差异维度（气质/色彩/材质）
- [ ] 明确的**混搭规则**：哪些可以混，混时的主导原则

## 5. 质量门槛（建完后自检）

| 检查项 | 通过标准 |
|---|---|
| 可辨识性 | 只看 Prompt Keywords，能否生成出**不同于其他风格**的图？ |
| 边界清晰 | 每个易混风格都有明确的区别说明？ |
| 引用有效 | 所有链接的目标文件存在（跑 `tools/validate.py`）|
| 元素支撑 | 至少 3 个原子元素页支撑这个风格（否则风格是空的）|
| 可生成 | 至少有一个可用的配方，或明确标注"待建配方" |

> **门槛**：若一个风格运动没有**至少一个完整配方**，它应标为 `status: draft`，
> 表示"图鉴已建，但尚未验证可用于产出"。

## 6. 建立顺序（推荐）

```
1. 先建运动/家族根页（定义 + 语法 + 边界）
2. 再建子风格页（各分支）
3. 然后补原子元素页（发型/妆容/材质/光影/配色…）
4. 再写配方（.yml → 校验 → .md）
5. 最后更新所有 index.md 与 log.md
```

**为什么这个顺序**：先定语法才能保证子风格不跑偏；
先有元素才能在配方里引用；先有配方才能验证风格是否真的可用。

## 7. 登记（必做）

新建风格包后，必须更新：

1. `atlas/taxonomy/movements/index.md` — 加入新风格条目
2. `atlas/index.md` — 若新增了元素维度子目录
3. `index.md`（根）— 更新"当前核心包"说明
4. `log.md` — 追加一行变更记录

**漏了第 4 步 = 资产库失去可追溯性**，视为未完成。
